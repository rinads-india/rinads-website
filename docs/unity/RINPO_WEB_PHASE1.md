# RINPO 3D on RINADS.com — Phase 1 integration contract

Status: WEB INTEGRATION SCAFFOLD ONLY. No actual 3D model or playable Unity Web build
has been uploaded or verified. Do not enable public marketing links until QA is complete.

## Production boundaries

- Existing Next.js website stays the public site and source of navigation/SEO.
- Existing RINPO provider/phone stays the sole chat experience; Unity never
  authenticates or directly queries Supabase.
- The Unity build is optional and loads only after an explicit visitor click.
- The existing approved PNG remains a truthful fallback; do not fabricate a 3D
  rendition from it. The approved rigged model must be imported separately.
- No changes to the current RINPO avatar widget, RINADS R monogram, tenancy or
  production auth. No Unity assets in Git or the normal website bundle.

## Create the separate Unity project

1. Install Unity Hub and a supported Unity 6 editor with Web Build Support.
2. Use the existing PRIVATE 'rinads-india/RINADS-RINPO' repository as the
   separate Unity source project (starter in draft PR #1 under /unity-rinpo).
   Initialize its Unity 6 project locally, not inside the deployed website.
3. Import the approved licensed and rigged RINPO 3D master. If unavailable,
   use basic scene geometry internally only, never present it as RINPO.
4. Add a minimal scene with RINPO, a camera, directional light, idle/wave
   animations and 3 Unity UI buttons: Talk to RINPO, Business OS, Book demo.
5. Copy starter/RinpoWebBridge.cs to Assets/Scripts/ and
   starter/RinpoWebBridge.jslib to Assets/Plugins/ in that Unity project.
   Attach the C# component to a scene GameObject and wire the 3 button events.
6. In Unity Web Player Settings use desktop/mobile performance profiling.
   Create a release Web build, using Brotli compression only when the
   hosting environment supplies the correct Content-Encoding headers.
   Use the Unity Web loader generated by the build rather than a CDN copy.

## Publish the build

Default same-origin build base path is '/unity/rinpo/v1'.
Alternatively set 'NEXT_PUBLIC_RINPO_UNITY_BASE_URL' to
'https://assets.rinads.com/unity/rinpo/v1'. Only these controlled locations
are accepted by the asset URL validator. The CDN must enable HTTPS, CORS for
www.rinads.com and the proper WebAssembly MIME/compression headers.

For a basic Brotli build, publish the generated Build and StreamingAssets
directories under the selected base, and create 'manifest.json' alongside them:

{
  "version": "1.0.0",
  "loader": "Build/rinpo.loader.js",
  "data": "Build/rinpo.data.br",
  "framework": "Build/rinpo.framework.js.br",
  "code": "Build/rinpo.wasm.br"
}

Replace these illustrative file names with EXACT output file names produced
by Unity. Static hosts must serve .br files with Content-Encoding: br,
.wasm.br with Content-Type: application/wasm, and JavaScript with an
appropriate JavaScript MIME type. For initial local smoke tests, an
uncompressed build avoids incorrect compression headers; update the
manifest to the corresponding plain filenames.

## Website activation

The /rinpo/3d route stays noindex and can be QA-tested directly.
The /rinpo marketing link is behind
'NEXT_PUBLIC_RINPO_UNITY_ENABLED=true'; leave it unset while the build,
approved model, QA or rollout is incomplete. Vercel environment changes
require a new deployment for NEXT_PUBLIC variables.

## Manual acceptance gates

- Never auto-load Unity on homepage or the global bottom-right RINPO widget.
- No interaction or animation alters the established RINPO image or logo.
- Explicit click loads the manifest, validates asset paths, shows progress.
- Missing files, WebGL 2 absence or loader errors fall back without taking
  down the existing website or RINPO chat.
- Unity 'Talk to RINPO' opens the real existing chat. The other two
  allowlisted actions navigate to public pages; no automatic business actions.
- Desktop Chrome, Firefox, Safari; iOS Safari and Android Chrome QA.
- Check reduced motion, keyboard navigation, touch controls, loading time,
  accessibility alternative and low-end phone memory use.
- Check deployment preview/production CORS, MIME types, Content-Encoding,
  CSP, cache invalidation, web analytics and no new Console errors.
- Run repository lint, typecheck, unit tests, build, and manual checks.
- Only after the Unity asset and CI are verified: review, merge and stage
  following docs/deployment/POLICY.md. Do not bypass active CI fixes.
